# 方法与审计轨迹

## 1. 研究问题

一个项目从签约到真正建成，中间丢掉了多少？签约时的企业名气和活动规模能否预测后续兑现？

## 2. 纳入规则

事件必须来自南阳市、县区政府或招商相关官方报道，并明确属于招商签约、项目推进日或重点签约项目队列。报道中只有协议、培训、销售合作等内容而没有可识别物理项目的，不进入项目队列。

事件按counting_role去重。全市主活动进入项目名额分母，县区同日细节页用于补充项目名称，不重复加总。可能属于全市活动子集的单项目页标为possible_subset_detail。

项目必须有明确名称，能够与县区和事件绑定。80项不是426个项目名额的随机样本，而是公开报道中能够建立身份并追踪的项目集合。

## 3. 时间窗口

签约窗口为2019至2022年，后续截止2025-12-31。最晚签约项目也有至少三年建设期。2026年出现的新信息不进入结果编码，以避免移动截止线。

## 4. 检索与人工审定

广域66项对每个项目执行两个查询：

1. 县区 + 完整项目名 + 开工 / 投产
2. 县区 + 企业名或特征词 + 项目 / 进展 / 竣工

脚本保留前8条高相关候选，共497条。关键词只用于排序，不自动决定状态。人工审定集中在curate_followups.py，每一个非默认状态都写入日期、主要来源、交叉来源、理由和证据等级。

淅川14项来自同一官方队列，沿用更严格的项目级物理证据核查。

## 5. 状态规则

- built：明确投产、试产、验收或投入运营。
- physical_progress：明确开工、主体建成、车间或设备进度，或官方文件显示进入投产调度。
- administrative_only：规划、备案、注册或审批，没有物理证据。
- later_mention_only：签约后再次出现，没有新增物理或行政节点。
- no_later_trace_located：广域检索未定位项目专属后续记录。
- no_physical_milestone_located：深审未定位项目专属物理里程碑。

## 6. 分析

主要结果是事件点名率、项目状态分布和强物理里程碑率。比例报告Wilson 95%置信区间。

逻辑回归只使用检索方法一致的66项广域队列。二元结果为是否有built或physical_progress。预测变量为知名企业信号和活动公布项目数的log标准化值。金额只有11/66项有可比数字，不进入模型。

模型是探索性检验，重点看优势比和置信区间。没有通过更换结局、子组或变量来追求显著性。

## 7. 影像规则

地图中的双图使用Esri World Imagery Wayback在各项目指示坐标和实际显示缩放级别的本地历史版本。build_wayback_pairs.py沿Esri tilemap变更链获取候选版本，下载同一中心瓦片并按SHA-256去重，保证每个项目展示的两个中心瓦片文件不同。影像元数据单独查询采集日期、供应商和分辨率。

配对优先按真实采集日期选择：左图为签约日之前最近一次可识别采集，右图为签约日之后且2025-12-31之前最近一次可识别采集。若该坐标没有签约后采集影像，则显示采集跨度最大的两个不同版本，并在页面明确说明没有证据将它们称为签约前后变化。Wayback版本日期只用于识别存档版本，不能代替采集日期。

广域队列使用县区中心指示点，淅川深审使用园区或乡镇指示点，均非项目宗地。每组影像只说明该指示点周边公开底图的变化，不用于确定项目建成状态，也不参与统计结论。

## 8. 可复现性

数据生成、搜索、人工审定、统计、影像配对、地图数据和PDF均由仓库脚本生成。运行verify.sh会检查行数、状态枚举、来源、模型输出、80组影像文件差异、网站资源和PDF页数。重新抓取Wayback版本时单独运行build_wayback_pairs.py；该脚本依赖Esri公开服务，不参与项目状态编码。

来源链接另由audit_sources.py独立检查。链接健康结果只说明页面在检查时能否访问，不自动改变已经人工审定的项目状态；若主证据永久失效，优先寻找同一政府体系内的替代原始来源并在curate_followups.py留下修订记录。
